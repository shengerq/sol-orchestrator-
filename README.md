# sol-orchestrator-
这个插件的核心作用是：让 Sol 负责项目规划、核心任务和最终审查，把边界明确的任务交给 Terra/Luna，从而提高并发效率并减少 Token。
执行流程
用户目标
  → Sol 制定 1～N 个任务
  → Sol 保留核心任务
  → Terra/Luna 执行委派任务
  → 每个任务写入独立结果文件
  → Sol 逐项审查
  → Sol 串行整合
  → 未完成则自动生成下一批
  → 独立复核通过后 goal_complete
可配置功能
功能	可选值	作用
模型	自定义 Sol、Terra、Luna	可填写部署的模型 ID 和接口
推理强度	none 到 xhigh	每个模型可以单独设置
任务数量	1～N、0	0 表示 Sol 自动决定
Token 模式	economy、balanced、quality	控制上下文和输出预算
执行方式	auto、api-parallel、host-agents	自动、API 并发或子对话执行
文件模式	compact、expanded	精简归档或保留全部过程文件
工作模式	auto、manual、documents	自动执行、人工配置或仅生成文档

默认使用 economy + compact + auto。
对话管理
每个子对话只能负责一个项目，绑定固定的 conversationProjectId，禁止把其他项目发送到已有对话。
对话开头采用：
P0001 | terra-5.6 | 完成插件并通过测试 | T02
聊天窗口还会显示“对话队列”，包含项目编号、模型、目标、任务内容和状态。
同一项目可以创建 N 个子对话。不过这些属于 Codex 宿主子代理，不是 N 个独立的顶层 UI 线程；顶层线程真实名称仍由 Codex 界面控制。
并发与文件安全
无依赖任务可以同时创建 N 个对话。
有依赖任务按波次执行，例如 T02 → T01。
每个对话拥有独立的提示文件和结果文件。
子对话只能读取共享项目，不能直接修改共享源码。
修改方案先写入自己的结果文件。
Sol 审查通过后，再按顺序应用修改。
已审查通过的任务不会重复执行或重复审查。
长期目标
使用：
/gaol 完成整个项目并通过全部测试
插件会持续保留这个最终目标。当前任务耗尽但项目尚未完成时，会调用 continue_goal 生成下一批任务，不会因为没有新任务而停止。
只有独立 Sol 复核确认完成后，才会返回：
goal_complete
文件存储
默认保存在当前项目内部：
sol-orchestrator-projects/
└── P0001/
    ├── PROJECT.md
    └── B01-运行编号/
        ├── run-bundle.json
        └── final-review.md
compact 模式完成后只保留项目主文档、合并归档和最终审查，减少废弃文件。
Token 降低方式
Sol 优先生成较少但边界明确的任务。
子模型只接收自己的任务上下文。
已通过任务不重复执行或审查。
长期目标只传递审查摘要，不重复传递完整历史。
economy 模式使用本地最终汇总，减少一次模型调用。
只有并发确实有收益时才增加任务数量。
